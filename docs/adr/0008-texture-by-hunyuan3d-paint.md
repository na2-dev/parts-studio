# テクスチャは Hunyuan3D-Paint 2.1 に作らせる（ADR-0006 を置き換える）

ADR-0006 では、TRELLIS.2 のボクセル属性場を視点別に塗って法線で合成する方式を採った。
しかし顔が最後まで直らなかった（[実測](../measurements/2026-08-30-face-quality.md) ほか）。
原因は色の**表現**にある。TRELLIS.2 は色を 3 次元のボクセル場として持つため、全身で格子を
分け合う。顔に割ける情報量が構造的に少なく、しかも「塗り」と「彫り」を区別できない。

Meshy も Tripo も、そして 3d-studio（Hunyuan3D）も、**幾何を条件に多視点の「絵」を生成し、
それを UV に焼く**方式である。顔は 2D の高解像度で描かれる。ここが決定的に違う。

そこで**形は TRELLIS.2 のまま、テクスチャ工程だけ Hunyuan3D-Paint 2.1 に差し替える。**

実測（RTX 4070 Ti SUPER・我々のリトポロジー済み 42,084 面メッシュに対して）:

```
Hunyuan3D-Paint 2.1   60.5秒 / VRAM 使用 12.99GB・確保 19.23GB / PBRマップ付き
```

3d-studio が同じ機体で測った数字（13.0GB・約70秒）と一致する。

そのうえで 3d-studio の手順どおり元絵を投影する（ADR は起こさない。`project_detail` は
道具であって決定ではない）。

```
1段目 全身 --mode=detail                        68.8秒 / 貼れた画素 46.53%
2段目 顔だけ --mode=color --top=0.26 --bottom=0.48  42.0秒 / 16.28%
```

## Consequences

- **ADR-0006（視点別に塗って法線で合成）は使わなくなる。** 実装（`gen_blend.py` の合成）は
  ボクセル場のプレビュー用としてのみ残る
- 環境が 1 つ増える。Hunyuan3D-2.1 は Python 3.12・別 venv・パッチが要る
  （3d-studio の `patches/hunyuan3d-2.1_all.patch`）
- **ライセンスが Tencent Community License に戻る**（EU・英国・韓国では利用不可、
  1M MAU 未満なら商用可）。ADR-0003 で TRELLIS.2 を選んだ理由の 1 つが消える。
  形は MIT のまま、テクスチャだけ制約が付く形になる
- `use_remesh` は必ず False。既定の True だと渡した形を作り直してしまう

## Considered Options

- **ボクセル場のまま解像度や合成を詰める**: 1536 まで上げても顔は改善せず、むしろ悪化した。
  guidance_strength も効かなかった。打ち止め。
- **元絵の投影だけで直す**: `project_detail` は「平らな面に描かれた模様」を戻す道具で、
  彫られた形は戻せない。TRELLIS.2 の色の上に当てても顔は染みのままだった。
- **形ごと Hunyuan3D-2.0 mv に戻す**: 確実だが、TRELLIS.2 の幾何の細かさ（背中の鍵穴が
  凹凸として出る、兜の突起 3 段）を捨てることになる。顔の問題は色の表現が原因と
  切り分けられたので、形まで替える必要はない。
