# テクスチャは視点ごとに塗り、面の法線で重みづけして合成する

[実測](../measurements/2026-08-30-shape-texture-separation.md)で、テクスチャの条件に何を渡すかが
部位ごとに正反対の要求を持つことが分かった。顔は正面からしか見えないので正面 1 枚で塗るのが最良で、
背中は背面からしか見えないので 4 視点で塗るのが最良になる。**1 つの条件で全面を塗る限り、
どちらかが必ず犠牲になる**（正面だけで塗ると正面の黄色が背中へ滲み、4 視点で塗ると目の虹彩が
茶色から青灰色に転ぶ）。

そこで、**視点ごとに 1 回ずつ塗り、各ボクセルの法線がどの視点を向いているかで重みづけして
合成する**。重みは `clamp(dot(法線, 視点方向), 0, 1) ** 4` を視点間で正規化したもの。
法線が引けないボクセル（実測で 14.3%）は中心からの外向きで代用する。

この方式で、顔は「正面 1 枚で塗った場合」と同等を保ちつつ、背中の黄色の滲みが消えた。

工程分離（ADR-0002）があるからこそ成立する。形は 1 回作れば据え置きで、塗りだけを 4 回繰り返す。

## 実測（1024・RTX 4070 Ti SUPER）

| | 所要 |
|---|---|
| テクスチャ工程の読み込み | 23s |
| 形の符号化 | 11s |
| 塗り（1 視点あたり） | 12〜15s |
| **合計（4 視点＋合成）** | **約 87s** |

VRAM 5.50GB / RAM 13.72GB。形の生成（193s・RAM 21.5GB）を含めても 5 分で終わる。

## 踏んだ罠

- `Trellis2TexturingPipeline.preprocess_mesh` は `(x,y,z) -> (x,-z,y)` の軸入れ替えをする。
  こちらの形は既に内部座標系なので、逆変換 `(x,y,z) -> (x,z,-y)` を先に当てて打ち消す。
  打ち消さないと形が寝たまま塗られる。
- `.ply` の面の向きが揃っていないと頂点法線が裏返り、視点の重みが非対称になる
  （実測で front 0.396 / left 0.131 / right 0.351 / back 0.122）。中心からの外向きに揃え直すと
  0.250 / 0.244 / 0.237 / 0.269 に収まった。**重みの対称性は、法線が壊れていないかの検算に使える。**

## Considered Options

- **正面 1 枚で塗る**: 顔は最良だが、正面の黄色が背中と脚に滲む。却下。
- **4 視点で塗る（multidiffusion）**: 背中は最良だが、目の虹彩が青灰色に転ぶ。却下。
- **形とテクスチャを同時に作る（上流のまま）**: 目が暗い穴になる。却下。
- **可視性で重みづけする（法線ではなく実際に描画して判定）**: より正確だが、描画を挟むぶん重い。
  法線で足りているうちは採らない。凹んだ部位で問題が出たら再考する。
